# Сквозное тестирование «Таваар Доставка»

Дата: 24 ноября 2026 года

## Ограничения безопасности

Текущая production-база и VK Cloud Storage являются рабочими. Отдельной тестовой БД, тестового bucket и набора тестовых аккаунтов в проекте нет. Поэтому в рамках безопасной проверки не создавались тестовые заведения, владельцы, администраторы, курьеры, клиенты, заказы и фотографии в production. Это предотвращает изменение реальных данных и отправку реальных уведомлений.

## Фото логотипа и обложки

В исходном коде обнаружена и исправлена проблема совместимости iPhone: Expo возвращает JPEG-байты при включённом `base64`, в том числе для HEIC-фотографий, а клиент мог объявлять эти байты PNG/WebP. Теперь клиент всегда отправляет корректный `image/jpeg`, использует совместимый режим iOS, после загрузки делает refetch и показывает пользователю успех или ошибку.

Исправление находится в commit `c838ea1` и проверено `pnpm check`, `pnpm test` и `pnpm build:web`. Его публикация на VPS не подтверждена: текущий SSH-сеанс периодически возвращает код 126 при распаковке/перезаписи файлов, а публичный HTML продолжает ссылаться на предыдущий asset.

## Что требуется для настоящего полного E2E

1. Отдельная MariaDB `tavaar_test` с отдельным `DATABASE_URL`.
2. Отдельный VK Cloud test bucket или mock storage.
3. Тестовые аккаунты без реальных телефонных номеров и уведомлений.
4. E2E runner и сценарии для web; для native — Detox или Appium.
5. Seed/cleanup fixtures для пользователей, ресторанов, меню, часов, курьеров и заказов.
6. Тестовый deployment, не связанный с `tavaar.online` и production webhook-ами.

Только после этого можно безопасно выполнить пункты полного сценария с созданием данных и реальными переходами статусов.
